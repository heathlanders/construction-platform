# Trade Knowledge Packs — Session Plan & Ledger

> **Purpose:** give every one of the 183 taxonomy trades knowledge depth (work steps, code refs,
> hazards, QA, inspection checklists, cost catalog, quantity rules, blueprint callouts) through one
> declarative pack per trade, in waves an agent can run unattended.
> **Load first:** `docs/Trade_Knowledge_Packs_v1_0.md` (spec) · `docs/trade-packs/RESEARCH_PROMPT.md` ·
> skill `trade-packs` · locked decisions T-59, T-63, T-64 (+ proposed T-66) · `CLAUDE.md` rules.
> **This file is the single source of state.** Every session reads it, does the next row, and updates
> it in the same PR.

## Run settings (owner edits these)
```
AUTO_MERGE: yes       # yes = agent merges its own PR after ci-local is green, then starts the next wave
MAX_WAVES_PER_RUN: 1  # how many waves one session/loop iteration may complete
```

```
agent's REVIEW_QUEUE lines, then review every pack yourself (scope of quantity rules, double counts,
source ids) and fix engine gaps the agents report before closing the wave. Then: gen:catalog-migration --wave NN --apply (if assemblies were added), pack:barrel,
`npx vitest run`, `npx tsc --noEmit`, scripts/ci-local.sh --report. Commit, push, open a PR (body ends
with the Claude Code line). Append to docs/trade-packs/REVIEW_QUEUE.md. Update this ledger row (State,
PR, one-line summary with counts). If AUTO_MERGE is yes and ci-local is green: merge the PR, then
continue with the next row up to MAX_WAVES_PER_RUN. If anything fails twice: set the row to
🔴 BLOCKED: <reason>, commit the ledger, stop.
Non-negotiables: never push to main; never edit an applied migration; no proprietary numbers (RSMeans/
NECA/ICC/NFPA tables); no machine-translated Spanish safety text; never invent URLs or code sections;
keep existing task-buildout/estimating snapshots unchanged unless a pack sets supersedes_hand with a
written reason; one heavy job (build/test/emulator) at a time on this machine.
```
